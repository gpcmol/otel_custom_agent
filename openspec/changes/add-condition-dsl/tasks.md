## 2. DSL tests — written first, comprehensive (all situations)

- [x] 2.1 `LexerTest`: every token class (identifier, `$`-root, numeric literal `int`/`long`/`double`, string literal `'...'` and `"..."`, every operator `|| && ! == != < > <= >= in + - * / %`, every punctuation `( ) [ ] , .`), rejection of unknown punctuation (`@`, `<=>`, `~`), whitespace handling, empty input rejection, positions carried for error messages.
- [x] 2.2 `ExpressionParserShapeTest`: every operator produces the correct AST node type; precedence is honoured (`a || b && c` parses as `a || (b && c)`); parentheses override (`(a || b) && c`); arbitrary nesting (`A && (B || C) && !D` produces the exact tree from design.md); collection literal `[1, 2, 3]` produces `List<Literal>`; `null`/`true`/`false` literals produce the right `Literal` type; `$this`/`$argN`/`$return` atoms produce `Property` leaves with the correct `RootSource`; dot+index paths reuse the existing `PathSegment` grammar.
- [x] 2.3 `TypeCheckerSuccessTest`: String equality (`$arg0.brand == 'BMW'`); numeric comparisons (`$arg0.mileage > 1000`, `<`, `<=`, `>=`, `!=`); `in` against typed collection literals (`$arg0.mileage in [0, 100000]`); `size` on `Collection`/array; `contains` on `String` and `Collection<String>`; `contains` on flattened `List<Person>` via `.name` → `List<String>`; `like`/`ilike` on `String`; `icontains` on `String` and `Collection<String>`; `$return` on a non-void method typed from the return type; `$return` on a `void` method typed as `Object` (accepted, runtime null-handling covers it); null-test forms (`$x == null`, `$x != null`).
- [x] 2.4 `TypeCheckerFailureTest`: String vs numeric mismatch (`$arg0.brand == 3`); unknown function (`unknownFunc($x)`); unknown property (`$arg0.nonexistent`); raw `Collection` element type (`size($arg0.rawList)` where `getRawList()` returns raw `List`); Map root (a leaf path that navigates into a `Map`); wrong function arity (`size($x, $y)`); `in` with mismatched element type (`$arg0.brand in [1, 2, 3]`); `contains` with non-String/non-Collection first operand (`contains($arg0.mileage, 100)`); each failure MUST throw `ExpressionCompileException` with the block id and a named category.
- [x] 2.5 `EvaluatorTest`: every operator's runtime behaviour with matching operands (`==`, `!=`, `<`, `>`, `<=`, `>=`, `in`, `+`, `-`, `*`, `/`, `%`); `&&` short-circuit (right term NOT evaluated when left is false — verify via a leaf that records evaluation); `||` short-circuit (right term NOT evaluated when left is true); `!` including `!null` → true; `!true` → false; `!false` → true.
- [x] 2.6 `EvaluatorNullHandlingTest`: `$x == null` true iff `$x` is null; `$x != null` true iff `$x` is non-null; `null == null` → true; `null != null` → false; any other comparison with a null operand → false (no `NullPointerException`); `size(null)` → 0; `contains(null, 'x')` → false; `like(null, "%x%")` → false; `ilike(null, "%x%")` → false; `icontains(null, 'x')` → false; runtime exception inside a leaf (an accessor that throws) → expression evaluates to false (swallowed, block skipped).
- [x] 2.7 `LikeMatcherTest`: prefix pattern (`like("BMW-X5", "BMW%")` → true); suffix pattern (`like("Piet", "%iet")` → true); contains pattern (`like("aPiEt某某", "%PiEt%")` → true); single-char wildcard (`like("Piet", "Pi_t")` → true; `like("Pi", "Pi_t")` → false — `_` matches exactly one char, not zero); empty pattern (`like("", "")` → true; `like("x", "")` → false); pattern longer than value (`like("ab", "abc%")` → false); no-match (`like("audi", "BMW%")` → false); case-sensitivity of `like` (`like("bmw", "BMW%")` → false); case-insensitivity of `ilike` with ASCII fold (`ilike("BMW", "bmw%")` → true; `ilike("Piet", "%IET")` → true); documented Unicode limitation (`ilike("ß", "SS")` → false, with a comment explaining ASCII fold).
- [x] 2.8 `ContainsIcontainsTest`: `contains("the BMW M5", "BMW")` → true (substring); `contains(List.of("vip", "user"), "vip")` → true; `contains` on a flattened `List<Person>` via `.name` path; `icontains("nl", "NL")` → true (whole-string case-insensitive); `icontains(List.of("VIP", "user"), "vip")` → true (element-wise); `icontains("the BMW M5", "Bmw")` → false (NOT substring — document); type-mismatch `contains(123L, 1)` fails at type-check (covered in 2.4 but cross-reference here).
- [x] 2.9 `SizeFunctionTest`: `size(List.of(1,2,3))` → 3; `size(new int[]{1,2})` → 2; `size(null)` → 0; `size($arg0.orders) > 5` end-to-end with a fixture returning a 6-element list → true; empty collection → 0; used in boolean expression (`size($x) > 0 && $arg0.brand == 'BMW'`).
- [x] 2.10 `ReturnOnVoidTest`: build an `ExitPoint` for a `void` method with `expr="$return == null"`; evaluate against a `null` returned value → true; build one with `expr="$return.foo == 'x'"`; evaluate → false (no exception); build one with `expr="$return != null"`; evaluate → false.
- [x] 2.11 `ExpressionParserFailureCategoriesTest`: each parse-failure category from 2.4 is also asserted at the `ExpressionParser.parse` level (the public entry) — the thrown `ExpressionCompileException` MUST carry the `class#method` block id (passed in via the entry signature) and a short category string suitable for the one startup warning.
- [x] 2.12 `ConditionSharedAccessorTest`: a `Property` leaf for `$arg0.brand` and an `<attribute path="$arg0.brand"/>` rule MUST resolve via the same `ValueResolver.resolve` call and hit the same `AccessorCache` entry — assert by resolving both through a shared `AccessorCache` instance and verifying the cache size grows by one, not two.
